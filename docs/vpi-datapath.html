1. 整体架构：VPI 作为虚拟化层
VPI 软件编排层
VPI 的核心工作 = 把同一块 DDR 物理内存包装成 VPIImage，然后告诉各芯片"去这个地址读/写"
芯片之间不传数据 — 它们共享同一块内存，各自通过 DMA 引擎 直接访问

3. 一帧数据的完整旅程
1
GStreamer 分配环形缓冲区
v4l2src ! video/x-raw,format=NV12 → GStreamer 在 DDR 中分配 4 槽环形缓冲区
每槽 = 1280×720 Y 平面 (900KB) + 640×360 UV 平面 (450KB) = 1.35MB
总缓冲区 = 4 × 1.35MB = 5.4MB (DDR 常驻，不释放)
2
VIC 硬件矫正 → DMA 写入环形缓冲区
VPI 收到 backend=VIC → 告诉 VIC 硬件"写 DDR 地址 0x..."
VIC 直接从相机 ISP 拿原始帧 → 畸变矫正 + 极线对齐 → DMA 写入环形缓冲区当前槽位
VIC 写完 → 更新描述符 write_ptr++ → 通知 PVA/DLA "有新帧可用"
3
PVA + DLA 同时 DMA 读取
VPI 告诉 PVA: "去 DDR 0x... 读左右图，跑 SGM"
VPI 告诉 DLA: "去 DDR 0x... 读左图，跑 YOLO"
两块芯片读的是同一块 DDR 物理内存 → 零拷贝
VIC 写完一帧 → PVA/DLA 读到的是完全一致的 NV12 数据
4
PVA 输出视差图到 DDR · CPU 读回
PVA 算完 SGM → DMA 写视差图 (+置信度) 到 DDR 另一块区域
GPU 同时从 DDR 读左图 crop(BBox) → ViTPose++ → 2D 关键点写回 DDR
CPU 从 DDR 读视差图 + 2D 关键点 → 三角化 3D
5
环形覆盖 — VIC 新帧覆盖最旧槽位
当 PVA/DLA 读完槽 N (释放 read_ptr) → 槽 N 标记为"空闲"
VIC 写完槽 N+1,N+2,N+3 → 下一个写位置绕回槽 0 → 覆盖最旧数据
如果 PVA 处理太慢 → read_ptr 落后 → 槽位耗尽 → VIC 等待或丢帧
4. VPI 到底做了什么 — 三个步骤
① 包装内存 → VPIImage
vpiImageCreateWrapper(pDDR, W, H, NV12)
不拷贝数据，只记录: 地址 + 宽高 + 格式 + 步长
VPIImage = DDR 物理地址的"视图"
② 创建 Payload → 分配临时缓冲
vpiCreateStereoDisparityEstimator(...)
在 PVA 内部 SRAM 分配 Census/Cost/SGM 工作区
Payload 里存的是 算法需要的临时内存，不是数据
③ 提交 Stream → 硬件执行
vpiSubmitStereoDisparityEstimator(stream, VIC|OFA|PVA, payload, left, right, ...)
VPI 把 VPIImage 的 DDR 地址传给硬件，硬件自己 DMA
Stream 保证顺序 · Event 保证同步
④ CPU 只管理描述符
CPU 不读写 NV12 数据，只维护 64 字节环形缓冲区描述符:
write_ptr / read_ptr / count / stride
更新描述符 ≠ 拷贝数据 · 描述符变更 ≈ 几十纳秒
5. 环形缓冲区视角的时序
一帧生命周期 · NV12 环形缓冲区 4 槽
VIC
写槽N ~8ms
PVA
读槽N → SGM ~12ms
DLA
读槽N → YOLO ~8ms
GPU
读左图crop → ViTPose++ ~25ms
CPU
读视差图+2D → 3D
槽 N: VIC 写完成(t=8) → PVA/DLA 开始读(t=8) → PVA 读完成(t=20) → 槽 N 释放
槽 N+1: VIC 在 t=0~8 写入(前一帧) → PVA/DLA 在 t=8~20 读取 → ...
4 槽足够: 最差情况 GPU 25ms + CPU 8ms = 33ms < 4×8ms=32ms → 接近临界，4 槽勉强够
6. 一句话总结
VPI 不做数据搬运 — 它只告诉每块芯片 "DDR 地址是多少"
环形缓冲区在 DDR 中，GStreamer 分配，VIC 写，PVA/DLA 读，同一块物理内存
CPU 只管理 64 字节描述符，数据全程 零 CPU 拷贝
MotionLabs · VPI 零拷贝多芯片数据流
